## Thin binding and effect model

The test-only driver binds `fcop.Project.rule_distribution(action=..., request=...)`, forwards the complete request without defaults/result rewriting and has no Manifest loader, dependency resolver, digest, projection or receipt algorithm. That public capability does not currently exist. This test binding does not add a production API; its absence raises `DistributionNotImplementedError.code=RULE_DISTRIBUTION_NOT_IMPLEMENTED`. No legacy fallback or private implementation import is used.

Requests supply fixed manifest/module/profile input paths, workspace identity, explicit selected modules/languages, fixed observation time and explicit ADMIN selection reference. They do not gain Core lifecycle authority. The facade action labels and result-field assertions are test adapters for the specified semantics, not current implementation claims.

All input and expected-value fixtures are confined to pytest temporary sandboxes. Package fixtures contain 18 raw artifacts with the fixed nine-module/73-clause schedule. Fixtures create no successful Host output or adoption/deployment receipt. Successful receipt setup in downstream cases goes through production adopt/deploy. The independent literal framing oracle calculates expected bytes only and never writes a production result. Every operation captures full directory/file/symlink facts before/after; read-only and missing-capability cases enforce zero writes. Rejection helpers require structured errors and rethrow missing capability rather than passing it.

Real race workers call apply after an independent-process barrier. Fault requests target public test-only materialization seams; no monkeypatch or production seam is introduced. Expected archive checks read wheel/sdist members and compare actual bytes, not merely filenames. These future postconditions are not yet demonstrated while the entry is absent.
