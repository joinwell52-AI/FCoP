# FCoP 4.0.0 / fcop-mcp 4.0.0

Stable promotion of the accepted `v4.0.0rc1` implementation, with no new protocol semantics or tool business behavior. The RC remains available and unchanged. Publication occurs only after ADMIN signs `FCOP_4_STABLE_RELEASE_READY`; a version string or this document is not evidence of publication.

The Core distribution provides workspace identity, four envelopes, lifecycle, relations, explicit Branch convergence, trusted authorization, durable idempotency, recovery and versioned rule distribution. The MCP adapter retains its frozen **46 Tools / 12 Resources / 4 Templates**, including `reopen_task`. Its Core dependency is `fcop>=4.0.0,<4.1.0`; install the exact pair together.

```bash
python -m pip install fcop==4.0.0 fcop-mcp==4.0.0
```

Use a fresh activated virtual environment. Before public release, install the corresponding locally verified wheel/sdist files from the WP4F Manifest instead of querying PyPI for the unpublished Stable version.

Package installation does not migrate existing workspaces, redeploy rules, adopt Profiles or update other applications. Current 3.x workspaces retain legacy behavior. Authorization-sensitive transitions require trusted initialization; caller-supplied roles, fields or evaluator code cannot create authority.

WP4F validates two independent builds, exact four-file hashes, Twine, full Windows/Ubuntu regression, Python 3.10–3.13 three-platform installed consumers, real MCP Branch/convergence/concurrency/retry/restart scenarios and publication dry-run. Live PyPI readback and the specifically authorized local MCP environment upgrade are Phase B actions after the release Gate. No Registry, Zenodo, CodeFlowMu or additional feature work is included.
