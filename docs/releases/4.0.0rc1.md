# FCoP 4.0.0rc1 — unpublished candidate

This is a verification target, not a published release. Neither PyPI, GitHub
Release, MCP Registry, Zenodo nor main has been updated by WP4D.

The accepted protocol and rule-distribution behavior is unchanged. Both package
identities target 4.0.0rc1 and are classified Beta. The exact MCP dependency is
`fcop>=4.0.0rc1,<4.1.0`; the stable 4.0.0 package pair is not admitted.

Acceptance is scoped to a fixed Git commit and four exact candidate artifact
hashes. The WP4D Manifest and its final-HEAD readback receipt are the evidence
authority; a source demo, intermediate green CI or an uploaded development
artifact alone is not `FCOP_4_RC_ACCEPTED`.

The original audit-guard blocker at 893e5c55f9f7ea433c6c518c76534218a4cf9570
remains historical fact. ADMIN erratum 22db1377163bb0b1e74c4b94fa1f594b3e762a9d
authorizes only the old test's major/minor precondition correction and WP4D
resumption, preserving its fixture and regression assertion.

Existing 3.x workspaces retain their original behavior and bytes until a
separately authorized migration. Existing published registry metadata and
citation identifiers remain unchanged. CodeFlowMu is a fixed read-only
compatibility consumer, never a target for this candidate deployment.

Even an ADMIN-signed RC acceptance Gate would not authorize tag creation,
publication, main merge, a registry update or any CodeFlowMu write.
